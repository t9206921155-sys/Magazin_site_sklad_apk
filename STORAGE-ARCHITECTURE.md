# Хранение базы и фотографий

## База данных

По умолчанию приложение использует SQLite:

```text
telegram-shop/data/shop.db
```

Путь можно переопределить переменной окружения `MAGAZIN_DB`. Это используется тестовым runner-ом, чтобы запускать изолированную временную базу.

SQLite хранит товары, пользователей склада, остатки по складам, заказы, настройки, журнал операций и метаданные фотографий. Для production файл `shop.db` должен находиться на постоянном диске VPS, а не в эфемерном контейнере.

## Режимы базы

В настройках склада: `⚙️ → Облако` доступны:

- **VPS / SQLite** — основная живая база находится на VPS в `data/shop.db`.
- **VPS → Supabase** — backend на VPS остаётся точкой доступа, а каталог может синхронизироваться с Supabase.
- **Direct Supabase** — после авторизации через VPS клиент получает только public/anon-конфигурацию Supabase. Service-role ключ клиенту не выдаётся.

Для текущего развёртывания рекомендуется начать с `VPS / SQLite`: проще резервное копирование и меньше внешних зависимостей.

## Где хранятся фотографии

Фотографии не должны храниться в SQLite как большие бинарные поля. Приложение использует объектное S3-хранилище:

```text
bucket: shop-photos
prefix: products
```

Поддерживаются S3-совместимые провайдеры, в том числе Yandex Object Storage, VK Cloud и другие. В настройках задаются endpoint, access key, secret key, bucket и регион. В базе сохраняются ссылки/метаданные фото, а само содержимое лежит в bucket.

Публичный URL формируется через S3 endpoint/CDN. Если облако не настроено, приложение может работать с локальными путями/URL, но для production это не рекомендуется: фото потеряются или станут недоступны при переносе VPS.

## Резервные копии

SQLite резервируется отдельно:

```text
bucket: shop-backups
prefix: sqlite
```

Фото и backup базы должны находиться в разных bucket-ах. Backup содержит базу и настройки, но не заменяет резервирование bucket-а с фотографиями.

## Production-чеклист

1. Подключить постоянный диск для `telegram-shop/data`.
2. Создать bucket `shop-photos` и prefix `products`.
3. Создать отдельный приватный bucket `shop-backups`.
4. Указать S3 endpoint, access key и secret key в настройках склада.
5. Нажать `Проверить` в разделе облака.
6. Загрузить тестовое фото и проверить его открытие после перезапуска.
7. Выполнить backup и убедиться, что появился объект в `shop-backups/sqlite`.
8. Не помещать access key и secret key в Git, frontend или APK.

## Yandex Disk API (заглушка)

В настройках добавлен провайдер `Yandex Disk API (заглушка)` и поля OAuth token/path. Токен намеренно не задан в репозитории: его нужно вставить администратору самостоятельно. До подключения REST-адаптера загрузка остаётся в режиме S3; это безопасный feature flag, не подменяющий рабочее хранилище.

## Единые контракты провайдеров

`telegram-shop/storage_contracts.py` содержит стабильные Protocol-контракты:

- `DatabaseProvider`: `ping`, `push_products`, `pull_products`;
- `PhotoStorage`: `enabled`, `ping`, `upload_photo`.

Новые провайдеры должны реализовывать эти методы и возвращать безопасный статус через `provider_status`, без credentials в ответе.
