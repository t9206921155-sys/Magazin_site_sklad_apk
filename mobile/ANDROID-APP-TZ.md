## 2. Цели приложения

1. Дать покупателю нативный вход в магазин без браузера: иконка, push, deep links.
2. Поднять конверсию и повторные заходы (push о статусе заказа, акциях, новинках подписанных витрин).
3. Присутствие в RuStore (ключевой канал РФ) + прямая раздача APK (как уже устроено у «Склада»).
4. Не сломать существующий канал продаж (сайт, Telegram Mini App) — приложение использует те же API.

Метрики успеха: installs ≥ 500 за первый квартал; retention D7 ≥ 15%;
конверсия push → заказ ≥ 3%; крашлесс-сессии ≥ 99,5%.

---

## 3. Два варианта реализации (решение — за владельцем)

### Вариант A — WebView-обёртка сайта («как Склад»), Фаза 1

Полностью повторяет проверенный путь `apk-build/`: нативная оболочка
(подключение к серверу, deep link `shop://`, иконка, splash) загружает
адаптивный сайт `/`. Каталог, корзина, оплата, чат работают через сайт.

- **Срок:** 1–2 дня работы.
- **Плюсы:** мгновенный результат, вся логика уже на сайте, поддержка = поддержка сайта.
- **Минусы:** push ограничены (WebPush в WebView нестабилен), UX браузерный, нет офлайн-корзины.

### Вариант B — полноценное React Native приложение, Фазы 2–6

Нативный UI на данных существующего API (см. §6). Ниже ТЗ описывает именно его.
- **Срок:** ~3–5 недель работы (см. §10).
- **Рекомендация:** сделать A сразу (быстрая раздача), параллельно начать B.
Вариант A не выбрасывается: он остаётся «лёгкой» сборкой для слабых устройств.

## 4. Функциональные требования (Вариант B)

### 4.1 MVP (v1.0 — обязательно)

| Модуль | Требования |
|---|---|
| Онбординг | Splash → выбор сервера (по умолчанию production) →guest_id генерируется и хранится локально |
| Главная | Баннеры/объявление (`/api/config` → announcement), топ-товары, рекомендации, категории |
| Каталог | Список с бесконечной прокруткой (`/api/catalog?page&per_page`), фильтры: цена от/до, состояние, продавец, только с фото, «можно поторговать», сортировки price_asc/price_desc/new/rating; категории/подкатегории |
| Поиск | Умный поиск с опечатками, автодополнение (`/api/search/suggest`), история запросов локально |
| Карточка товара | Галерея (свайп, зум), цена/старая цена, бейджи, состояние + дефекты, параметры товара, продавец (рейтинг, «проверенный»), кнопки: в корзину, **предложить цену** (`/api/offers`), **забронировать** (`/api/reservations`), **написать продавцу** (`/api/chat/*`), **пожаловаться** (`/api/complaints`); похожие товары |
| Корзина | Локальная (как на сайте), промокод, пересчёт, офлайн-доступность |
| Оформление | Способы доставки (`/api/delivery/*`, расчёт СДЭК/5POST), способы оплаты (`/api/payment/methods`), создание заказа (`POST /api/orders`), оплата (см. §5) |
| Заказы | Список и статусы (`GET /api/orders?guest_id=`), повтор заказа |
| Профиль | Guest-профиль + (опц.) привязка Telegram; контакты, версия приложения, проверка обновлений APK |
| Push (FCM) | Статус заказа (оплачен/отправлен/доставлен), ответ продавца в чате, цена принята (offers). Токен → `POST /api/mobile/register` |
| Deep links | `shop://product/{id}`, `shop://catalog`, `shop://order/{id}`; App Links на домен (assetlinks.json) |
| Локализация | ru (MVP); строки вынесены в ресурсы |

## 5. Оплата в приложении (ограничения)

- MVP: все способы, кроме крипты, открываются веб-редиректом на платёжную страницу (как на сайте) — возвращает покупателя в приложение через deep link `shop://order/{id}`.
- v1.1: нативные SDK ЮKassa/Т-Банка (требуют ИП/юрлицо и ключи) и СБП-модуль.
- CryptoBot/Stars — только редирект (нативных SDK нет).

## 6. API-контракт

### 6.1 Используем существующие эндпоинты (ничего не ломаем)

```
GET  /api/config                     — магазин, доставка, оплата, объявление
GET  /api/catalog                    — q,cat,sub,condition,seller,price_min,max,
                                       has_photo,negotiable,sort,page,per_page
                                       → products,total,page,pages
GET  /api/search/suggest?q=          — автодополнение
GET  /api/recommendations?product_id — похожие; /api/recommendations/recent
GET  /p/{id} данные через /api/catalog или отдельный /api/product/{id} (добавить)
POST /api/orders                     — {items[{id,qty}],customer,delivery_method,
                                       payment_method,promo_code,bonus_spend}
GET  /api/orders?guest_id=           — заказы покупателя
POST /api/delivery/calc | /api/delivery/points
POST /api/offers | GET /api/offers?buyer_key=
POST /api/reservations | GET /api/reservations?buyer_key= | DELETE /api/reservations/{id}
POST /api/complaints
POST /api/sellers/{slug}/subscribe | /unsubscribe | GET /api/my/subscriptions?user_key=
GET  /api/chat/threads|messages|unread (требуют Telegram-авторизацию)
```

### 6.2 Добавить на бэкенде (мало, назад-совместимо)

1. `GET /api/product/{id}` — полная карточка одним запросом (сейчас карточку собирает SSR).
2. `POST /api/mobile/register` — `{guest_id, fcm_token, platform:"android", app_version}`; хранение в новой таблице `mobile_devices`; замена токена при повторной регистрации.
3. Отправка FCM: статусы заказа (`confirm_payment`, `set_order_status`), новое сообщение чата, ответ на offer. Секрет FCM — `FCM_CREDENTIALS_JSON` в env (как остальные секреты, только через .env).
4. `GET /api/app/version?platform=android` — текущая версия/ссылка на APK (можно переиспользовать `/api/releases/android`).
5. Rate limit на новые публичные эндпоинты (уже есть middleware блок 15).

## 7. Нефункциональные требования

| Параметр | Значение |
|---|---|
| ОС | Android 6.0+ (API 23), target API 34 (как «Склад») |
| Размер APK | ≤ 25 МБ (RN: включить Hermes, ABI-сплиты) |
| Cold start | ≤ 2 c на среднем устройстве |
| Сеть | Только HTTPS в production; `usesCleartextTraffic` запрещён (для локальной отладки — debug-сборка) |
| Хранение | guest_id/токены — EncryptedSharedPreferences/KeyStore; платёжных данных на устройстве нет |
| Приватность | Никаких сторонних трекеров; аналитика — только агрегированные события (опц. Метрика); оферта и политика в приложении |
| Доступность | Контраст, размеры шрифтов системы, TalkBack по ключевым сценариям |
| Стабильность | Crashlytics-аналог (опц. Sentry self-hosted) или локальные логи + `/metrics` сервера |

## 8. Технологический стек (Вариант B)

- **React Native 0.75+ / Expo SDK 52** (managed workflow, EAS Build — сборка без локального Android Studio, CI-friendly) + `expo-router` (навигация/deep links).
- Состояние: `zustand` + `react-query` (кеширование API, retry, offline-флаги). Локальное хранилище: `react-native-mmkv` (шифрование).
- Push: `@react-native-firebase/messaging` (FCM) — единственная нативная зависимость с конфигом (google-services.json от владельца).
- Сборка: EAS Build → APK/AAB; подпись — тот же подход, что у «Склада» (keystore вне git, в секретах CI).
- Вариант A (обёртка): чистый Gradle-проект по образцу `apk-build/android`.

**Почему Expo:** сборка и обновления без полной студии, OTA-обновления JS-части (CodePush-подобный механизм через EAS Update), минимальный порог входа.

## 9. Публикация и раздача

1. **RuStore** — приоритет №1 (аудитория РФ): карточка, скрины, политика, подпись AAB.
2. **Прямая раздача APK** — как у «Склада»: страница `/download/app` + QR + deep link `shop://install`.
3. **Google Play** — опционально (при выходе на другие рынки); TWA/assetlinks для App Links.
4. Обновления: проверка версии при старте (`/api/app/version`) + мягкий баннер; принудительное обновление при ломающем API (min_supported_version в конфиге).

## 11. Критерии приёмки (общие)

- [ ] Все сценарии MVP выполняются на реальном Android 8/12/14 (телефон + планшет).
- [ ] Отключённый сервер: приложение показывает офлайн-корзину и понятную ошибку, не крашится.
- [ ] Пуш приходит при смене статуса заказа; тап открывает нужный экран.
- [ ] Секреты (ключи FCM/подписи) не попадают в git; сборка воспроизводима из CI.
- [ ] Нагрузка на API не выше сайта: кэш react-query, пагинация, без поллинга чаще 30 с.
- [ ] Регрессия сервера зелёная (новые эндпоинты покрыты тестами в `tests/`).
- [ ] Скриншоты экранов и публикации — в блок-отчёт (без секретов).
