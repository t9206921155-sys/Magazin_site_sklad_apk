# 📘 Telegram Shop + Android «Склад» — пошаговая инструкция

Это единая практическая инструкция: как устроен проект, как поднять сервер, как подключить APK склада, как работает база, как включить облако для картинок, как создавать товары, генерировать тексты и выкладывать позиции на витрину.

## 1. Как устроен проект

Проект состоит из 5 уровней:

1. **Сайт / витрина** — каталог, карточки товаров, SEO-страницы.
2. **Telegram-бот + Mini App** — продажи и сценарии через Telegram.
3. **Админка `/admin`** — управление магазином, оплатами, доставкой, ИИ, продавцами, витриной.
4. **Склад `/warehouse/`** — рабочее место сотрудника: товары, фото, остатки, штрих-коды, печать.
5. **Android APK `Склад`** — нативная обёртка над `/warehouse/`.

Главное правило:

> **APK не подключается напрямую к базе данных.**
> Он подключается к вашему серверу `https://ваш-домен/warehouse/`, а сервер уже работает с базой, облаком и интеграциями.

## 3. Шаг 1 — поднять сервер проекта

### Вариант A: локально

```bash
cd telegram-shop
pip install -r requirements.txt
cp .env.example .env
python bot.py
```

После запуска будут доступны:
- `http://localhost:8000/`
- `http://localhost:8000/admin`
- `http://localhost:8000/warehouse/`
- `http://localhost:8000/app`

### Вариант B: production / Docker

Из корня репозитория:

```bash
./deploy/deploy.sh --domain https://example.com --expected-version 1.0.6
```

Или вручную:

```bash
git fetch origin
git checkout arena/continue-marketplace-content
git pull --ff-only origin arena/continue-marketplace-content
cd telegram-shop
pip install -r requirements.txt
cd ..
docker compose down || true
docker compose build --no-cache
docker compose up -d
```

## 4. Шаг 2 — заполнить `.env`

Минимально важные настройки:

```env
BOT_TOKEN=...
ADMIN_IDS=123456789
ADMIN_PASSWORD=свой_пароль
WEBAPP_URL=https://ваш-домен
PAYMENT_PROVIDER=test
BOT_MODE=polling
HOST=0.0.0.0
PORT=8000
```

Что это значит:
- `ADMIN_PASSWORD` — вход в `/admin`
- `WEBAPP_URL` — главный публичный домен проекта
- `BOT_TOKEN` — нужен для Telegram-бота
- `ADMIN_IDS` — Telegram ID админов

## 5. Шаг 3 — войти в админку и сделать базовую настройку

Откройте `/admin`.

Рекомендуемый порядок:

1. войти в админку;
2. сменить тестовый пароль, если он ещё не заменён;
3. указать название магазина;
4. проверить тексты, валюту, контакты;

## 6. Шаг 4 — как работает база данных

### База по умолчанию

По умолчанию проект использует **локальную SQLite-базу** на сервере. Для первого запуска этого достаточно.

То есть сразу после старта:
- сайт,
- склад,
- админка,
- Telegram-сценарии

уже работают с одной общей базой проекта.

### Что значит “подключить APK к базе”

На практике это означает:

1. поднять сервер;
2. открыть `/warehouse/` на этом сервере;
3. в APK указать адрес `https://ваш-домен/warehouse/`.

Сам APK с MySQL/SQLite напрямую не общается.

## 8. Шаг 6 — как работать со складом

Откройте `/warehouse/`.

Через склад можно:
- создавать товары
- загружать до 20 фото
- задавать артикул и штрих-код
- вести остатки
- задавать место хранения и владельца
- включать/выключать показ на витрине
- печатать этикетки
- публиковать товар
- массово редактировать позиции

### Базовый сценарий добавления товара

1. нажать `+`
2. заполнить название
3. добавить фото
4. указать цену
5. указать остаток
6. задать артикул / штрих-код
7. указать место хранения
8. оставить товар **на витрине**, если он должен быть виден на сайте
9. сохранить

## 9. Шаг 7 — как товар попадает на витрину

У товара есть флаг **показывать на витрине**.

Если он включён, товар появляется:
- на сайте
- в каталоге
- в карточках товара
- в Mini App
- в публичной части проекта

Если выключен:
- товар остаётся в складской базе,
- но покупатели его не видят.

Чтобы товар реально вышел на витрину, обычно нужно:
1. заполнить название;
2. добавить фото;
3. поставить цену;
4. указать наличие / остаток;
5. оставить включённым флаг витрины.

## 11. Шаг 9 — как настроить склад в APK

При первом запуске приложение попросит адрес сервера.

Введите:

```text
https://ваш-домен/warehouse/
```

После этого приложение:
- сохранит адрес;
- откроет склад внутри WebView;
- даст сотруднику войти под своим логином/паролем.

Если путь `/warehouse/` не указан, приложение старается добавить его автоматически.

## 12. Шаг 10 — как подключить APK быстрее через deep link и QR

### Deep link

Поддерживаются ссылки:

```text
sklad://connect?url=https://ваш-домен/warehouse/
```

```text
sklad://setup?url=https://ваш-домен/warehouse/
```

- `connect` — подключить сразу
- `setup` — только подставить адрес на экран настройки

### QR onboarding

Доступны QR-endpoints:
- `/api/releases/android/qr.svg?mode=connect`
- `/api/releases/android/qr.svg?mode=setup`

И готовая страница для сотрудников:
- `/download/android`

Там уже есть:
- APK
- deep links
- QR-коды
- подсказки по подключению

## 13. Шаг 11 — как работает сканер в APK

В APK склад открывается в WebView.

Сценарий сканирования такой:

1. пользователь нажимает кнопку сканера;
2. сначала используется web scanner через `BarcodeDetector`;
3. если WebView на устройстве работает нестабильно, включается **native fallback scanner**;
4. считанный код возвращается в интерфейс склада;
5. по коду выполняется поиск / приёмка / продажа / инвентаризация.

Это сделано специально, чтобы Android-приложение было устойчивее на реальных устройствах.

## 14. Шаг 12 — как подключить облако для картинок

Облако настраивается **не в APK**, а в самом складе:

- `/warehouse/` → `⚙ Настройки` → `Облако`

Поддерживаются варианты:

1. **S3-совместимое хранилище**
   - Selectel
   - Cloud.ru
   - VK Cloud
   - Яндекс Object Storage
   - MinIO
   - свой S3 endpoint

2. **Supabase**
3. **MySQL / MariaDB**

### Рекомендуемый порядок

Для большинства случаев лучший вариант такой:
- каталог хранить на основном сервере проекта;
- картинки вынести в **S3**;
- включить отдачу фото из облака;
- при желании включить автосинхронизацию.

### Настройка S3 пошагово

1. открыть настройки облака;
2. выбрать S3-провайдера;
3. указать `endpoint`, `access key`, `secret key`, `bucket`, `region`;
4. нажать **Проверить подключение**;
5. нажать **Синхронизировать**;
6. включить **Подтягивать фото с облака**;
7. при желании включить **Автосинхронизация при сохранении**.

Что получится:
- старые фото выгрузятся в облако;
- новые фото можно синхронизировать автоматически;
- сайт и склад смогут использовать облачные URL;
- картинки будут грузиться быстрее.

## 15. Шаг 13 — как подключить внешний MySQL / MariaDB

Это нужно, если вы хотите внешний каталог товаров не только в локальной SQLite.

Настройка:
- `/warehouse/` → `⚙ Настройки` → `Облако` → `MySQL / MariaDB`

Заполняются поля:
- host
- port
- user
- password
- database
- table

Порядок:
1. выбрать `MySQL / MariaDB`
2. ввести параметры подключения
3. сохранить
4. нажать **Проверить подключение**
5. при необходимости выполнить синхронизацию

Важно:
- APK всё равно не ходит в MySQL напрямую;
- с MySQL работает сервер;
- если нужны и внешний каталог, и быстрые фото, часто используют связку **MySQL + S3**.

## 16. Шаг 14 — как подключить Supabase

Если хотите использовать Supabase:

1. выбрать `Supabase` в облаке;
2. указать `URL` проекта;
3. указать ключ;
4. указать bucket для фото;
5. сохранить;
6. проверить подключение;
7. синхронизировать каталог и фото.

Этот режим подходит тем, кто хочет вынести каталог и storage в managed cloud-сервис.

## 17. Шаг 15 — как генерировать тексты и контент

Есть два уровня генерации.

### Внутри склада

Для товара можно генерировать:
- название
- описание / текст объявления
- пост для публикации

Это удобно сотруднику прямо с телефона.

### В админке

В админке доступны:
- SEO-тексты
- рекламные тексты
- поиск аналогов
- баннеры
- видеоролики

### Что нужно настроить

В админке укажите параметры ИИ-провайдера:
- API URL
- API key
- модель

После этого можно:
1. открыть карточку товара;
2. вызвать ИИ-функцию;
3. получить результат;
4. сохранить или отредактировать текст.

## 18. Шаг 16 — как создать объявление и опубликовать товар

Есть несколько сценариев.

### Сценарий A — выложить на свою витрину

Самый простой сценарий:

1. создать товар в складе;
2. заполнить название, фото, цену, остаток;
3. оставить включённым показ на витрине;
4. сохранить.

После этого товар становится виден на сайте.

### Сценарий B — опубликовать в Telegram / VK

Нужно настроить в админке или в настройках склада:
- Telegram channel
- VK group id
- токены / доступы

После этого можно:
- публиковать товар вручную кнопкой у товара;
- включить автопубликацию новых товаров.

### Сценарий C — выложить в Avito

Поддерживаются два режима:

#### Через API
- указываются `client_id`, `client_secret` и прочие параметры Avito;
- можно создавать, обновлять и закрывать объявление.

#### Через XML feed
- используется ссылка `/avito/autoload.xml?key=...`;
- Avito периодически забирает каталог сам.

## 19. Шаг 17 — как печатать этикетки

В складе есть профили принтеров.

Поддерживаются:
- PDF
- ZPL
- EPL

Порядок:
1. открыть склад;
2. выбрать товар или несколько товаров;
3. нажать печать;
4. выбрать профиль принтера;
5. получить PDF или `.prn`.

## 20. Шаг 18 — как работает команда

Склад рассчитан на несколько сотрудников.

Есть:
- роли `admin` и `worker`
- журнал действий
- индикатор синхронизации
- быстрый вход по PIN
- биометрия WebAuthn
- push-уведомления

То есть один сотрудник добавляет или меняет товар, а другие видят это в общей базе.
