## Цель

Дать владельцу цифры: что продаётся, что лежит мёртвым грузом, сколько
денег заморожено в остатках.

## Контекст

Уже есть:

- `GET /admin/api/reports` (`api.py`, ~строка 1610) — базовая сводка;
- `GET /admin/api/reports/sellers` и `.pdf` — отчёт по продавцам;
- `pdfreport.py` — готовая инфраструктура PDF с кириллицей (шрифты DejaVu);
- журнал операций склада `wh_log` и журнал сканов `wh_scans` в `store.py`;
- заказы с позициями — `store.orders()`.

## Задачи

- [ ] `GET /api/warehouse/reports/turnover` — оборачиваемость за период:
      продано штук, выручка, средний остаток, коэффициент оборачиваемости
- [ ] `GET /api/warehouse/reports/dead-stock` — не продавалось N дней
      (параметр `days`, по умолчанию 60)
- [ ] `GET /api/warehouse/reports/stock-value` — стоимость остатков
      в закупочных и розничных ценах, разбивка по категориям
- [ ] `GET /api/warehouse/reports/abc` — ABC-анализ по выручке (A 80%, B 15%, C 5%)
- [ ] PDF-версии через `pdfreport.py`
- [ ] Раздел «📊 Отчёты» в UI склада
- [ ] Тесты `tests-block07.py`

## Критерии приёмки

- [ ] Отчёты считаются на пустой базе без деления на ноль
- [ ] Период задаётся `date_from` / `date_to`, некорректные даты → **422**
- [ ] Товары без продаж попадают в dead-stock, с продажами — нет
- [ ] Сумма ABC-групп равна общей выручке
- [ ] PDF открывается и содержит кириллицу без «квадратиков»
- [ ] Регрессия: 20/20, 8/8, 23/23

## Замечание

Цены — целые рубли (см. ограничения в `ROADMAP.md`). В отчётах округление
не накапливать: суммировать целые, а не округлять каждое слагаемое.
