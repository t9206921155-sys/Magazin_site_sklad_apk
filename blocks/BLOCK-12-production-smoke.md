# Блок 12 — Production health-check и post-deploy smoke

**Статус:** ✅ выполнено

## Цель
Автоматически понять после деплоя, работает ли сайт, API, авторизация, база и ключевые интеграции.

## Задачи
- [ ] `/health/live` без авторизации.
- [ ] `/health/ready` с проверкой БД и конфигурации.
- [ ] `scripts/post_deploy_smoke_check.sh` для домена.
- [ ] Проверка страниц, warehouse login, catalog, reports и cloud status.
- [ ] Безопасная работа без вывода секретов.
- [ ] Документация запуска и exit codes.

## Приёмка
- [ ] smoke проходит на staging и production.
- [ ] падение любого обязательного компонента даёт ненулевой код.

## Отчёт

- Добавлены `/health/live` и `/health/ready` с безопасным ответом и проверкой БД.
- Smoke-check проверяет публичные страницы, API и, при наличии `WH_LOGIN`/`WH_PASSWORD`, авторизованные складские endpoint-ы.
- Тест health включён в `run-tests.sh`.
- Секреты не выводятся в логи и не передаются в аргументах smoke-скрипта.
- Проверены shell-синтаксис и Python-синтаксис; полный набор тестов запускается через CI с установленными зависимостями.
