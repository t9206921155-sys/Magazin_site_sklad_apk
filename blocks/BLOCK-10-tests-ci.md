# Блок 10 — Тесты и CI

**Статус:** ⏳ запланировано
**Зависит от:** —
**Оценка:** половина сессии

---

## Цель

Собрать разрозненные тесты в один прогон и запускать их автоматически
на каждый push.

## Контекст

Сейчас три независимых набора, 51 тест:

| Файл | Тестов | Запуск |
|---|---|---|
| `telegram-shop/tests-labels.py` | 20 | `python3 tests-labels.py` |
| `telegram-shop/tests-hid-scanner.js` | 8 | `node tests-hid-scanner.js` |
| `telegram-shop/tests-stage5.py` | 23 | нужен запущенный сервер |

Проблемы: разные раннеры, `tests-stage5.py` требует живой сервер и лезет
в боевую базу, нет единой команды и нет автозапуска.

## Задачи

- [ ] `run-tests.sh` в корне — поднимает сервер на свободном порту с
      временной базой, гоняет все наборы, гасит сервер, возвращает
      суммарный код выхода
- [ ] Изолировать `tests-stage5.py` от боевой базы (`MAGAZIN_DB` во временный файл)
- [ ] `.github/workflows/tests.yml` — прогон на push и pull request
- [ ] Бейдж статуса в `README.md`
- [ ] Проверка `python3 -m py_compile` для всех модулей и `node --check` для JS
- [ ] Линтер конфигов: `.env.example` содержит все ключи, читаемые `config.py`

## Критерии приёмки

- [ ] `./run-tests.sh` проходит с нуля на чистом клоне
- [ ] Тесты не оставляют мусор в базе и не требуют ручной очистки
- [ ] CI краснеет при намеренно сломанном тесте
- [ ] Прогон укладывается в 5 минут

## Замечание

В CI ставить зависимости из `requirements.txt` с кэшем pip, иначе каждый
прогон будет тянуть reportlab и boto3 заново.
