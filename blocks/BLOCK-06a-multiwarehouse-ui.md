# Блок 06a — Мультисклад: интерфейс

**Статус:** ⏳ запланировано
**Зависит от:** блок 06 (выполнен — API готов и покрыт тестами)
**Оценка:** половина сессии

---

## Цель

Дать кладовщику работать с несколькими складами из интерфейса. Сейчас
backend полностью готов, но UI всегда использует склад по умолчанию.

## Контекст

Готовые эндпоинты (блок 06, покрыты `tests-block06.py`):

| Эндпоинт | Что делает |
|---|---|
| `GET /api/warehouse/warehouses` | склады, доступные пользователю, + `default` |
| `POST/PUT/DELETE /api/warehouse/warehouses[/{id}]` | управление (только admin) |
| `GET /api/warehouse/products/{pid}/stock` | разбивка остатков по складам |
| `POST /api/warehouse/products/{pid}/stock` | установить остаток на складе |
| `POST /api/warehouse/transfer` | перемещение между складами |
| `GET/PUT /api/warehouse/users/{uid}/warehouses` | доступы сотрудника |
| `POST /api/warehouse/scan` | принимает `warehouse_id` |

Файл интерфейса — `telegram-shop/warehouse/app.js`, разметка —
`warehouse/index.html` (шапка со строкой `#syncbar`).

## Задачи

- [ ] Селектор текущего склада в шапке, выбор сохранять в `localStorage`
- [ ] Глобальная переменная `CURRENT_WAREHOUSE`, подставлять в `scan`
      и операции с остатками
- [ ] В карточке товара показывать разбивку по складам
- [ ] Кнопка «Переместить» в карточке: склад-источник, приёмник, количество
- [ ] Раздел «Склады» в настройках (только admin): список, создание,
      переименование, удаление
- [ ] В управлении пользователями — чекбоксы доступа к складам
- [ ] Если склад один — селектор скрывать, чтобы не усложнять интерфейс

## Критерии приёмки

- [ ] Переключение склада меняет остатки в списке товаров
- [ ] Сканирование списывает с выбранного склада, а не с default
- [ ] Сотрудник видит в селекторе только свои склады
- [ ] Перемещение из UI отражается в разбивке сразу
- [ ] Выбранный склад переживает перезагрузку страницы
- [ ] `node --check warehouse/app.js` без ошибок
- [ ] Регрессия: 20/20, 8/8, 23/23, 33/33
- [ ] Нет `mode change` в коммите
