## Отчёт

### Критичный баг — service worker кэшировал API

`warehouse/sw.js` применял **cache-first ко всем GET**, включая
`/api/warehouse/*`. Последствия на живом складе:

- после первой загрузки список товаров и **остатки переставали обновляться**;
- кладовщик видел неактуальные цифры и мог продать то, чего нет;
- данные не оживали, пока не сбросишь кэш браузера;
- в кэш попадали ответы `/api/warehouse/settings` — **с ключами облака**.

Переписанные стратегии:

| Запрос | Было | Стало |
|---|---|---|
| Оболочка (HTML/JS/иконки) | cache-first | cache-first (верно) |
| `GET /api/...` | **cache-first** | **network-first**, кэш — аварийный фолбэк |
| `POST/PUT/DELETE /api/...` | не обрабатывались | очередь IndexedDB + Background Sync |
| Логин, настройки, ключи | кэшировались | `isSensitive()` — не кэшируются |

Кэш разделён на `SHELL_CACHE` / `API_CACHE`, версия `wh-v2`, старый `wh-v1`
удаляется при активации.

### Офлайн-очередь

Изменяющие операции без сети складываются в IndexedDB и отдают
`202 {queued: true}`. При появлении сети отправляются автоматически
(Background Sync, тег `wh-sync`, плюс ручной flush по событию `online`).
Ответы `4xx` снимаются с очереди, сетевые ошибки — остаются до следующей попытки.

В UI индикатор в шапке меняет цвет и текст: «📴 Нет сети · в очереди: N»,
«⏳ Отправляем отложенные операции», «⚠️ Данные из кэша». Ответ
`X-From-Cache: 1` подсвечивается.

### Обмен с 1С — не было выгрузки остатков

Существовали `/1c/catalog`, `/1c/orders`, `/1c/orders/ack`,
`/1c/orders/status`, но **не было способа обновить только остатки**.
`POST /1c/catalog` идёт через `importer.apply_import()`, который пропускает
позиции без `name` и создаёт новые товары — 1С была обязана слать полный
каталог целиком ради обновления остатков.

Добавлено:

- `POST /1c/stock` — `{"items": [{"code": "НМ-001", "stock": 12, "price": 990}]}`.
  Обновляет только `stock` / `price` / `old_price` / `in_stock` у существующих
  позиций. Названия и фото не трогает, новые товары не создаёт. Возвращает
  `{updated, not_found}`.
- `GET /1c/stock` — текущие остатки для сверки.
- `Store.update_stock_by_code()` — поиск по `code`, фолбэк на `name`;
  `stock=0` снимает товар с продажи.

Ограничения: максимум 5000 позиций (413), нечисловые значения игнорируются
без падения, токен обязателен.

**Тесты** — `tests-stage5.py`, 23/23 passed: обновление остатка и цены,
сохранность названия, `stock=0 → in_stock=false`, частичный успех с
неизвестным кодом, валидация (403/422/413), видимость на складе,
целостность старых 1С-маршрутов, стратегии в `sw.js`.

**Не покрыто:**
- офлайн-очередь на реальном устройстве (логика в тестах, UX на телефоне нет);
- Background Sync не поддерживается в Safari/iOS — фолбэк на `online`;
- боевая 1С — проверено на моках.
