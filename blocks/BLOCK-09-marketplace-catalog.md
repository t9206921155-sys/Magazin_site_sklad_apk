## Отчёт финальный (сессия 08.09.2026) — блок закрыт

### Найденные баги

1. **SSR `/catalog` отдавал 500 на любом запросе** — в `_render_catalog`
   использовались свободные имена `price_min/price_max/has_photo/negotiable/sort`
   (NameError, api.py:592). Страница каталога сайта была полностью сломана,
   регрессия страниц её не ловила (гнались только API-тесты). Исправлено.
2. **SSR-роуты не принимали параметры фильтров** — цена/сортировка/фото/торг
   были доступны только в API. Теперь `/catalog`, `/catalog/{cat}`,
   `/catalog/{cat}/{sub}` принимают `price_min, price_max, sort, has_photo,
   negotiable, seller, condition, q, page`, а фильтры сохраняются в ссылках
   пагинации и canonical.
3. **Фильтр «только с торгом» не работал нигде** — у товара не было поля
   `negotiable` (фильтр проверял несуществующий ключ `allow bargaining`).
   Добавлена колонка `products.negotiable` (миграция), поддержка в
   `_apply_product_fields`, чекбокс в кабинете продавца.
4. **`sort=rating` был заглушкой** — сортировал по несуществующему полю
   `seller_rating` товара. Теперь рейтинг продавца берётся из
   `store.seller_rating` (с memo на продавца в пределах запроса).

### Что сделано

- Общий код фильтров `_apply_catalog_filters` — один для SSR и API (устранён дрейф).
- Пагинация `/api/catalog`: `page`, `per_page` (клампится 0..100), в ответе
  `total`, `page`, `pages`; совместимо со старыми клиентами (`per_page=0` — без нарезки).
- Валидация параметров: мусор в числовых полях → 422 FastAPI, отрицательные → кламп,
  неизвестный `sort` → без сортировки. Никаких 500.
- SSR: форма фильтров (цена от/до, сортировка, «только с фото», «можно поторговать»)
  в `catalog.html`, сброс, фильтры в canonical и пагинации.
- Кабинет продавца: чекбокс «🤝 Можно поторговать» в форме товара.
- Аудит `MARKETPLACE-PLAN.md`: все разделы сверены с кодом, статусы проставлены.
  Чат, эскроу, верификация, тарифы, партнёрка, торг — оказались реализованы ранее
  и теперь отмечены. Остаток разнесён по блокам 16, 20–24 и бэктлогу.
