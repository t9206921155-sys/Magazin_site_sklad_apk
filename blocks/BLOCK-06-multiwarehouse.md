# Блок 06 — Мультисклад и роли

**Статус:** ⏳ запланировано
**Зависит от:** блоки 01–05 (выполнены)
**Оценка:** одна сессия

---

## Цель

Поддержать несколько складов в одной базе: у товара появляется привязка к
складу, остатки считаются по каждому складу отдельно, сотрудник видит только
свои склады.

## Контекст

Сейчас склад один и неявный: остаток лежит прямо в `products.stock`.
Роли уже есть — `admin` / `worker` в таблице `wh_users`
(`store.py`, метод `wh_add_user`, проверка в `api.py` → `wh_user_from_headers`).

Ключевые места:

- `store.py` — `wh_users()`, `wh_add_user()`, `_apply_product_fields()`,
  `update_stock_by_code()`, `_change_stock()`;
- `api.py` — блок `/api/warehouse/*` (примерно строки 1880–2400);
- `warehouse/app.js` — список товаров `loadList()`, форма товара, настройки;
- миграции — `store.py`, метод `_migrate_columns()`.

## Задачи

- [ ] Таблица `warehouses`: `id`, `name`, `address`, `is_active`
- [ ] Таблица `wh_user_access`: какой пользователь к каким складам допущен
- [ ] Таблица `stock_by_warehouse`: `product_id`, `warehouse_id`, `qty`
      (существующий `products.stock` оставить как суммарный — для витрины)
- [ ] Миграция: создать склад «Основной» и перенести в него текущие остатки
- [ ] `GET/POST/PUT/DELETE /api/warehouse/warehouses` — управление (только admin)
- [ ] Параметр `warehouse_id` в списке товаров, сканировании и приёмке
- [ ] Селектор текущего склада в шапке UI
- [ ] Ограничение: `worker` видит только разрешённые ему склады
- [ ] Перемещение между складами: `POST /api/warehouse/transfer`
- [ ] Тесты `tests-block06.py`

## Критерии приёмки

- [ ] Миграция на существующей базе не теряет остатки
- [ ] Товар с остатками на двух складах отдаёт корректную сумму на витрину
- [ ] `worker` без доступа к складу получает **403**
- [ ] Перемещение списывает с одного склада и приходует на другой атомарно
- [ ] Перемещение количества больше остатка → **400**
- [ ] Сканирование в режиме `sell` уменьшает остаток нужного склада
- [ ] Регрессия: 20/20, 8/8, 23/23
- [ ] Нет `mode change` в коммите

## Риски

- Миграция затрагивает боевые данные — обязателен бэкап перед выкаткой
  и проверка на копии базы.
- `products.stock` используется витриной, ботом и 1С — менять его семантику
  нельзя, только дополнить разбивкой по складам.
